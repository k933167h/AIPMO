AIPMO Runbook v1.4

설치

.env.example을 .env로 복사하고 PMO_API_KEY와 POSTGRES_PASSWORD를 변경한 뒤 docker compose up --build를 실행합니다.

GANTT-AX JSON

POST /api/v1/ganttax/imports, GET /api/v1/ganttax/imports/{import_id}/export. 모든 반입은 STAGED이며 승인 기준선이 아닙니다.

일정 CPM

POST /api/v1/schedule/cpm에 tasks: [{id,duration,predecessors:[id]}]를 전송합니다. ES/EF/LS/LF, 여유시간 및 주공정 작업을 반환합니다. 현재 FS·지연 0·경과일 기준만 지원합니다.

테스트

python -m pytest -q. CI는 PostgreSQL 테스트 서비스를 포함합니다.

운영·장애

401은 API 키, 422는 입력 및 순환 의존성, DB 오류는 DATABASE_URL 및 PostgreSQL 상태를 확인합니다.

증빙

CI 실행 기록, import ID, SHA-256, STAGED 상태를 확인합니다.

v1.5 의존성 유형

POST /api/v1/schedule/cpm에서 predecessors에 문자열 ID 또는 {id, type, lag} 객체를 전달합니다. FS·SS·FF·SF 및 양수 Lag/음수 Lead를 지원합니다. 현재 경과일 기준이며 공휴일과 근무일 달력은 지원하지 않습니다.

검증: python -m pytest -q. 오류 422가 발생하면 순환 의존성, 누락된 선행 작업, 잘못된 유형과 Lag를 확인합니다.

v1.6 근무일 달력

POST /api/v1/schedule/cpm 요청에 project_start: YYYY-MM-DD, holidays: [YYYY-MM-DD], working_weekdays: [0,1,2,3,4]를 추가합니다. 응답에는 작업별 날짜와 project_finish_date가 추가됩니다. 현재 정수 일수만 지원하며 시간 단위 및 국가별 공휴일 자동조회는 지원하지 않습니다.

v1.7 기준선 편차 분석

CPM API 요청에 project_start 및 baseline 객체를 전달합니다. baseline에는 approval_status APPROVED와 tasks 배열의 id, start_date, finish_date가 필요합니다. 결과 baseline_variance에서 시작·종료 편차와 지연·신규·삭제 작업을 확인합니다. 승인 여부는 입력값 검사만 수행하며 서버의 승인 이력과 대조하지 않습니다.

v1.8 기준선 승인

POST /api/v1/baselines에 project_code와 baseline.tasks를 전달하면 STAGED 기준선 ID가 생성됩니다. POST /api/v1/baselines/{baseline_id}/approve에 reviewer를 전달하면 승인 상태가 변경됩니다. CPM API에서 baseline_id를 지정하면 승인된 기준선만 조회하여 편차를 계산합니다. 현재 reviewer는 입력 문자열이며 독립적인 권한 검증은 지원하지 않습니다.

v1.9 SME 승인 자격증명 및 감사

서버 환경변수 PMO_SME_APPROVAL_KEY를 설정합니다. 승인 요청 시 기존 x-api-key 외에 x-sme-key 헤더를 전달합니다. 승인 성공 시 PostgreSQL 감사 테이블에 APPROVED 이벤트가 함께 저장됩니다. GET /api/v1/baselines/{baseline_id}/audit에서 PROPOSED/APPROVED 이력을 확인합니다. 현재는 공용 SME 비밀키이므로 개인별 RBAC 및 변조방지 증빙 저장소가 추가로 필요합니다.

v2.0 사용자별 SME 승인·반려

PMO_IDENTITIES_JSON에 토큰별 user_id와 roles: [SME]를 구성합니다. 승인·반려 요청은 x-api-key, x-sme-key, x-identity-token을 전달합니다. 승인 요청 reviewer는 토큰에 등록된 user_id와 일치해야 합니다. POST /api/v1/baselines/{baseline_id}/reject는 reason을 받으며 REJECTED 감사 이벤트를 남깁니다. 현재 SSO 연동이 아닌 정적 구성 기반 권한 검사이며 반려 사유는 영속 감사 로그에 저장되지 않습니다.

v2.1 OIDC 인증

PMO_AUTH_MODE=oidc, PMO_OIDC_ISSUER, PMO_OIDC_AUDIENCE 및 HTTPS PMO_OIDC_JWKS_URL을 설정합니다. 승인과 반려 요청의 x-identity-token 헤더로 RS256 JWT를 전달합니다. 서명, issuer, audience, expiration, subject 및 SME 역할을 검증합니다. 실제 기업 IdP 테스트와 감사 해시 체인은 추후 구현합니다.

v2.2 감사 해시 체인 검증

신규 승인 감사 이벤트는 prev_hash 및 event_hash SHA-256 값을 기록합니다. GET /api/v1/baselines/{baseline_id}/audit/verify에 x-api-key를 전달하여 체인 무결성을 확인합니다. 기존 데이터베이스에는 prev_hash/event_hash 컬럼 마이그레이션이 필요합니다. DB 관리자 수준의 변조를 방지하는 WORM 저장 및 외부 서명 체크포인트는 향후 개발 범위입니다.

v2.3 MCP 프로젝트 관리 정책

GET /api/v1/mcp/tools는 도구 목록을 조회하고 POST /api/v1/mcp/policy/check는 도구·역할·승인 정책을 시뮬레이션합니다. 실제 MCP 실행은 제공하지 않습니다. 요청자가 입력하는 roles와 approved는 신뢰할 수 없으므로 실행 권한 판단에 사용하지 마세요.

v2.4 GitHub Snapshot

POST /api/v1/integrations/github/snapshot accepts issues, pull_requests, workflow_runs arrays and returns normalized project metrics. Direct GitHub API fetching is not yet supported.

v2.5 GitHub 읽기 연동

서버에 PMO_GITHUB_READ_TOKEN을 읽기 전용 권한으로 설정한 후 GET /api/v1/integrations/github/{owner}/{repo}/sync를 호출합니다. Issue, PR, CI 실행을 조회하고 제목의 WBS-ID 표기를 연결 후보로 추출합니다. WBS 확정 변경과 GitHub 쓰기는 실행하지 않습니다.

v2.6 WBS 다중 시스템 통합

POST /api/v1/wbs/reconcile에 jira, plane, ganttax, github_links 배열을 입력하면 WBS별 연결 결과, 미매칭 항목, 동일 출처 중복 검토 여부를 확인할 수 있습니다. Jira와 Plane의 실제 원격 연결은 후속 버전에서 제공합니다. 정규화 결과만으로 확정 공정률을 산정하지 않습니다.

v2.7 Jira·Plane 원격 조회

PMO_JIRA_URL, PMO_JIRA_EMAIL, PMO_JIRA_TOKEN, PMO_PLANE_URL, PMO_PLANE_TOKEN을 서버 비밀 설정으로 지정한 뒤 POST /api/v1/wbs/reconcile/remote에 jira_project, plane_workspace, plane_project 및 선택적 ganttax, github_links를 전달합니다. 첫 페이지 최대 100건만 조회합니다. 실제 서비스 연동 검증과 프로젝트별 접근 제어는 추가 작업이 필요합니다.

v2.8 여러 페이지 WBS 통합

POST /api/v1/wbs/reconcile/paged에 jira_project, plane_workspace, plane_project, max_pages(1~5, 기본 3), ganttax, github_links를 입력합니다. 각 서비스 최대 500건 조회가 가능하지만 전체 데이터 보장은 아닙니다. 실제 증분 동기화 및 접근 권한 정책은 아직 제공하지 않습니다.

v2.9 프로젝트 접근 통제와 변경분 필터

서버 PMO_ALLOWED_PROJECTS에 허용된 Jira 프로젝트 키와 Plane 프로젝트 ID를 쉼표로 지정합니다. POST /api/v1/wbs/changes에 jira_project, plane_workspace, plane_project, updated_since(시간대 포함 ISO 날짜)를 입력하면 읽은 페이지에서 변경된 항목을 분류합니다. 누락된 갱신시각은 별도로 보고합니다. 이는 실제 증분 API나 체크포인트 저장이 아니므로 전체 변경 내역을 보장하지 않습니다.
